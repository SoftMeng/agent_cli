# Agent CLI v0.1 开发路线图

> v0.1 = M0 + M1 + M2 + M3 的最小可运行骨架。基于 Rig 0.40、单一职责 / 模块化 / 组件化、No TestCase、Low code comments。

## 一、目标与边界

**v0.1 在范围内**

- OpenAI / Anthropic 双 Provider 流式对话
- 4 个基础工具（read_file / write_file / run_command / add_memory）的注册与调用
- 本地 Skill 目录扫描 + 解析 + 注入 preamble
- 基于 `InMemoryConversationMemory` 的多轮历史（按 `conversation_id` 隔离）
- Ratatui TUI 多卡片渲染（Text / Thinking / Tool）

**v0.1 不在范围内（推迟到 v0.2+）**

- Skill 下载（git clone / 网络源）
- 命令白名单 / 沙箱
- 向量记忆 / 长期记忆压缩
- 多 Agent 编排、子 Agent、Plan-and-Execute
- Web UI / 远程服务化
- 任何形式的单元 / 集成测试代码

## 二、里程碑总览

| 里程碑 | 名称 | 价值 | 关键产出 | 验收 |
|--------|------|------|----------|------|
| M0 | 工程地基 | 代码能编译 | Cargo 依赖 / 模块骨架 / `lib.rs` 声明 / `main.rs` 启动 | `cargo check` 通过；`cargo run` 进入 TUI 占位 |
| M1 | Agent 直跑 | 模型能说话 | config + provider + builder + 最小 preamble | 输入提示词后流式输出文本（无工具） |
| M2 | 工具闭环 | Agent 能做事 | 4 个基础 Tool + `ToolServerHandle` 接入 + REPL | 模型自动调用工具，TUI 展示 tool_call / tool_result 卡片 |
| M3 | 技能与记忆 | Agent 有脑子 | Skill Registry + `InMemoryConversationMemory` + Prompt 注入 | 新会话可加载技能目录；同 `conversation_id` 多轮保留上文 |

> v0.1 = M0 + M1 + M2 + M3 的最小版本。

## 三、模块任务分解

### 3.1 config

- 任务：AppConfig 结构体 + `from_yaml_file` + `to_runtime_config`
- 产出：`src/config/mod.rs`、`config.yaml.example`
- Skill：`harness-rust-development`

### 3.2 agent

- 任务 A：provider 枚举（OpenAI / Anthropic）+ 工厂方法
- 任务 B：builder 接收 Provider / ToolServer / Memory，组装 `Agent<M, P>`
- 产出：`src/agent/{mod, provider, builder}.rs`
- Skill：`harness-rust-development`
- 风险：OpenAI / Anthropic 泛型不同；用枚举分发 + 单态化

### 3.3 tools

- 任务：4 个组件，每文件一个 Tool
- 产出：`src/tools/{mod, file, command, memory, skill}.rs`
- Skill：`harness-rust-development`
- 风险：`ToolServer::new().tool(T).run()` 与 `.tool_server_handle()` 互斥

### 3.4 skill

- 任务：扫描 `skills/<name>/SKILL.md`，解析 frontmatter（name / description）
- 产出：`src/skill/{mod, registry, frontmatter}.rs`
- Skill：`harness-rust-development`

### 3.5 memory

- 任务：`InMemoryConversationMemory` 适配 + `Arc<dyn ConversationMemory>` 注入
- 产出：`src/memory/mod.rs`
- Skill：`harness-rust-development`

### 3.6 preamble

- 任务：加载 `AGENT_PROMPT.txt`，注入技能列表与 memory_dir
- 产出：`src/preamble.rs`
- Skill：`harness-rust-development`

### 3.7 terminal

- 任务 A：`TerminalGuard`（raw mode RAII）
- 任务 B：`ChatCard` / `CardType`（Text / Thinking / Tool）
- 任务 C：`draw_ui`（ratatui 渲染）+ `sanitize_for_tui`
- 任务 D：事件到命令映射（`events.rs`）
- 产出：`src/terminal/{mod, cards, render, guard, events}.rs`
- Skill：`harness-rust-development`

### 3.8 app

- 任务 A：`session.rs` 消费 `StreamedAssistantContent` / `StreamedUserContent`，构建卡片
- 任务 B：`repl.rs` 主循环（事件 → stream → draw_ui）
- 产出：`src/app/{mod, repl, session}.rs`
- Skill：`harness-rust-development`
- 风险：流式分片到卡片映射、Reasoning 边界、tool_call 与 tool_result 配对

## 四、风险与依赖

| 风险 | 影响范围 | 缓解 |
|------|----------|------|
| OpenAI / Anthropic 类型不同 | `agent/provider.rs` | 用枚举 + 工厂返回 `AnyAgent`；具体类型不外泄 |
| `ToolServer` 与 `tool_server_handle` typestate 互斥 | `agent/builder.rs` | 统一走 `ToolServerHandle` 入口，禁用 `.tool()` 链式 |
| `Tool::call` 签名变更（rig 0.40 新增 `ToolContext`） | 所有 `tools/*` | 严格按 `rig::tool::Tool` 0.40 trait 实现 |
| 流式 ToolCall 与 ToolResult 配对丢失 | `app/session.rs` | 用 `internal_call_id` 做关联键 |
| Reasoning 片段噪声 | `terminal/render.rs` | 折叠连续 delta，独立 `CardType` |
| `InMemoryConversationMemory` 进程内 | `memory/*` | v0.1 可接受；v0.2 接 `rig-memory` |
